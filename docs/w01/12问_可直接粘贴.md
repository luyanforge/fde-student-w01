# 沈总访谈 · 预约目的 + 12 问投放脚本

## 预约目的（正式版，约 200 字）

作为产品方 FDE 团队成员，我希望在正式推进前与您做一次约 45 分钟的首轮沟通。目的不是介绍产品功能，而是先把您邮件里提到的"会员复购连续四个季度下滑"这件事问清楚：具体是哪个指标在下滑、我们怎么理解这个指标、您判断的会员老化有哪些依据，以及日常运营中从"找出该经营的会员"到"真的触达会员"这一段目前是怎么做的、卡在哪里。同时想确认您对结果的期望与验收方式，明确数据、系统和协作上前置条件，以及预算和决策路径。沟通后我会给出一份判断：这件事值不值得继续、接下来需要查什么找谁、能先验证哪一部分。这次我不会做任何功能或效果数字上的承诺。

## 预约目的（精简版，约 80 字）

作为产品方 FDE 团队，希望用约 45 分钟先问清复购下滑的具体口径与依据、目前运营的实际做法与卡点、您对结果的期望与验收方式，以及数据、协作和决策的前置条件。目标是给出"是否继续、先查什么、能先验证哪一部分"的判断，不做功能或效果承诺。

## 投放节奏（核心策略：前重后轻，一次投 3 条）

> 原则：**单条短（30 字内），一次投 3 条同簇问题**。省轮次，也避免他一次答成一大段套话。
> 每批把**最想拿到的放第 1 条**——他很可能只答前两条。

| 轮次 | 投放问题 | 簇的逻辑 |
| --- | --- | --- |
| R1 | ① 复述理解 + 四季度下滑的报表出处 | 先校准前提，再要基线 |
| **R2（现在发）** | ② 复购率怎么算？谁那边有数<br>③ 会员老化依据是什么<br>④ 谁在挑名单？最近一次怎么做 | 指标 → 归因 → 现状，一条线问下来 |
| R3 | ⑤ 名单到触达，卡在哪一步<br>⑥ 80 万活跃哪个系统出的？活跃怎么算<br>⑦ 最后在哪个系统打标签 | 链路 → 数据来源 → 写回系统 |
| R4 | ⑧ 小林拿到建议照着做还是再判断<br>⑨ 三个月后拿什么向董事会汇报<br>⑩ 上个项目最后哪步没做成 | 用法 → 验收 → 失败教训 |
| R5 | ⑪ 哪些事明确不能做，比如自动发券<br>⑫ 预算批了吗、谁拍板？能给脱敏数据吗 | 边界 → 进入条件 |

**合计 12 问，5 轮问完。**

## 各题要拿到什么（答完对照）

| # | 问题 | 必须拿到 | 拿不到时的处理 |
| --- | --- | --- | --- |
| ① | 复述 + 报表出处 | 一句"对/不对" + 报表名或数值 | 记 `unknown`，报告写"发起人未提供基线" |
| ② | 口径 + 谁有数 | 口径主张 + 具体人名 | 走 ⑫ 问数据路径 |
| ③ | 老化依据 | 有材料 / 明确没有 | `reported` 且无支撑，写成假设 |
| ④ | 谁挑名单、最近一次 | 一个具体事例 | 关键题，答偏就补问 1 次 |
| ⑤ | 卡在哪一步 | 最痛的一环 | `unknown`，报告写待核实 |
| ⑥ | 80 万来源、活跃定义 | 系统名 + 定义 | 与 ⑫ 合并处理 |
| ⑦ | 打标签的系统 | 系统名 + 是否涉及写操作 | 标"系统适配/待判断" |
| ⑧ | 建议怎么被使用 | 照做 / 再判断 | 决定确认点位置 |
| ⑨ | 三个月汇报什么 | 他的排序 | 关键题，决定承诺边界 |
| ⑩ | 上个项目哪步没做成 | 具体环节 | 风险清单依据 |
| ⑪ | 不能做什么 | 至少 1 条 | "暂不承诺"依据 |
| ⑫ | 预算、拍板人、数据可得 | 状态 + 人名 + 审批路径 | 第三问只能写条件句 |

## 若他答偏，只补这一句

| 场景 | 补问 |
| --- | --- |
| 只给结论不给依据 | 这个结论是哪次分析得出来的？ |
| 说"数据都有" | 哪位同事能导？要走审批吗？ |
