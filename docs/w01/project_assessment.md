## 一、结论

**建议带条件继续**：进入范围明确的小范围验证，不进入全面开发，不给出效果承诺。

**已获客户确认的范围与验收**（双方确认，非我方单方主张）：

- 首期只做"识别 + 建议"：输出下降会员名单、每人的下降情况与建议理由；**不含**标签执行、发券、对外触达、写回现有系统。
- 验收以"流程跑通 + 小林认可名单可用"为准；复购率变化**不作为**本期验收条件。
- 三个月为发起人个人期望，**不是交付期限，也不是验收标准**（三次沟通表述一致）。

**三个进入前提**（任一未落实则验证不启动）：

1. 数据线对接牵头人确定（当前在沈总手上，将与王经理、老周碰后告知）；
2. 一批可用于内部验证的脱敏历史会员与订单数据，含覆盖时间范围说明；
3. 小林可安排一次沟通，用于确认"名单可用"的判断标准。

| 判断为"会员老化比较明显" | `MAIL-W01-001`、`MSG-00832` | 客户本人承认这是其判断，数据能否支持尚未核实 | 是否有分层分析、备选归因 |

### 2.2 三层问题的区分

把"复购下滑"当作一个整体来处理是行不通的，它至少包含三个层次，且只有第二层是本期可动的：

1. **业务结果层**：复购率为什么下滑。归因未验证（"老化"是发起人判断），无基线数值，无口径。**本期无法回答，也不应承诺回答。**
2. **工作过程层**：谁在什么时候、用什么方式挑出该经营的会员，怎么给建议、怎么用。**这是产品可以嵌入的位置，也是本期唯一可验证的层次。**
3. **能力供给层**：标准产品能否在客户的语义与数据条件下产出可用的名单与建议。**这是 fit-gap 要回答的问题。**

### 2.3 值得优先改善的工作假设

当前工作依赖运营小林个人经验完成"挑名单"，发起人对此的具体做法"没有可确认的细节"（`MSG-00832` 后一轮）。这提示两件事：

- 该工作尚未流程化，若成立，则标准化工具的价值空间较大；
- 但同时意味着**没有现成的判断标准可对照**，验证时必须先与小林确认"什么算可用"，否则验收会失去依据。

**这两点是假设，不是结论。** 依据仅来自发起人转述，W1 未取得小林本人的说明。

| 安排项 | 内容 |

## 七、承诺边界

本期及可预见的下一阶段，我方**不作**以下承诺：

1. 三个月内复购率止跌回升，或任何提升幅度／准确率数字；

3. 将标签或建议写回青禾现有会员系统；
4. 在未与业务方确认判断标准前，声称名单"准确"或"可用"；
5. 以教学样例的运行结果代表青禾环境的适配结果。

## 九、工程备注：环境、模型与适配改动

本节记录实际运行条件与一处适配改动，供复核与后续周次对照。

**模型与端点。** 使用 Kimi Code 的 OpenAI 兼容端点 `https://api.kimi.com/coding/v1/chat/completions`，模型 `k3-256k`，请求配置取 `compatible`（不附加厂商专用推理参数）。密钥仅存于本机文件，不进入代码、命令行与公开运行记录。

**适配改动（一处）。** 该端点对 JSON Schema 校验较严：工具参数中只写 `enum` 而未声明 `type` 会被拒绝，返回 `400 ... properties.tag: type is not defined`。产品的 `prepare_tag.tag` 正是这种写法，导致动作类用例在首次运行中失败（`http_action`、`idempotency`、`undo`、`reject_change` 四项报 `MODEL_HTTP_400`）。

按任务书"不同模型的接口不兼容时修改适配器并保留证据"的要求，改动限定在**模型适配器层**（`platform/fde_product/models.py` 新增 `normalized_tools()`）：仅按 `enum` 取值推断缺失的 `type`，不改工具名称、描述、必填项与业务语义，业务代码 `agent.py` 未改动。改动前后同一请求的对照证据：无 `type` → HTTP 400；补 `type` → HTTP 200。

**运行结果（修复后重跑）。**

| 项 | 结果 |
| --- | --- |
| `verify_product.py --live` | 11/11 用例通过（`clarification`、`analysis`、`missing_coverage`、`readonly`、`http_action`、`idempotency`、`undo`、`date_text`、`date_button`、`reject_change`、`refund_explanation`），耗时 4 分 30 秒 |
| `environment_check` 9 项 | 全部 `pass`，`model_mode=live` |
| `model_baseline` | 9 次带 trace 的运行，失败 0 |
| Promptfoo `0.122.2` | 7/7 通过，失败 0、错误 0，合计 53,349 token |
| `check_product.py --root .` | `status: pass`，`errors: []` |
| 回归测试 | `pytest` 38 passed |

**已知边界。** 上述运行全部发生在产品自带的松果生活样例数据上（3 门店／9 会员／14 订单），与青禾优选的 80 万会员规模、真实会员与订单结构无关，不得据此推断客户环境下的表现。`k3-256k` 为推理模型，单次工具调用约 10 秒量级，各任务的耗时与成本需按客户模型重新测量。`evaluation` 仅代表基础评估通过，建议质量与是否过度承诺仍需人工复核。
